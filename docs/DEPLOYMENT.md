# Развёртывание после согласования

Публикация в этой редакции не выполнялась. Сайт полностью статический: HTML, CSS, JavaScript и WebP. Серверная часть, база данных и API не нужны.

## Что готово

`npm run build` воспроизводимо создаёт `dist/` и самодостаточный HTML. `npm run check` выполняет локальные проверки. GitHub Actions собирает и проверяет проект на push и pull request, затем сохраняет закрытый артефакт сборки. Секреты для этого не нужны. GitHub Pages не настроен.

`deploy/yandex-deploy.yml.disabled` содержит подготовленный шаблон публикации. GitHub его не выполняет: файл расположен вне `.github/workflows` и имеет неактивное расширение.

## После медицинского и визуального утверждения

1. Создать отдельный бакет Yandex Object Storage для этого проекта. Не использовать бакет VERBA Heart.
2. Настроить статический хостинг с `index.html` и HTTPS. Включение общего доступа к объектам делает сайт публичным; этот шаг требует отдельного разрешения владельца проекта.
3. Создать сервисный аккаунт с правом записи только в этот бакет. Сохранить ключ доступа в GitHub Environment Secrets, не в исходниках.
4. Задать `YC_BUCKET` как переменную окружения GitHub `production`, а `YC_ACCESS_KEY_ID` и `YC_SECRET_ACCESS_KEY` как Secrets этого окружения. Ограничить доступ и настроить required reviewers для production.
5. Перенести неактивный шаблон в `.github/workflows/yandex-deploy.yml`. После утверждения релиза запускать вручную. При последующем отдельном согласовании можно добавить запуск на push в защищённую ветку main.
6. Проверить опубликованный адрес на настоящем iPhone/Safari, включая прокрутку, паузу, смену ориентации и системный режим уменьшения движения. Не отправлять адрес пациенту до утверждения.

Для публикации копируется только `dist/`. Не загружать `baseline`, `docs`, `tests`, Git-историю или ZIP исходников. Скрипт сборки очищает временный QA-стенд. Загрузка не использует удаление объектов бакета и не меняет права доступа.

В репозитории сохранены исходная контрольная v0.2, восемь сцен, изображения, медицинский лист согласования, результаты QA и автоматическая проверка. GitHub Pages и публикация на Yandex не включены.

Закрытый веб-просмотр использует отдельный Sites-проект, доступный только владельцу после входа в ChatGPT. Он не предназначен для передачи пациенту. Исходники для будущего Yandex-развёртывания остаются обычным статическим HTML/CSS/JavaScript.
